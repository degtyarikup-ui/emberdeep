# Emberdeep — обязательные правила

**Перед первой правкой в сессии прочти файл `AGENTS.md` в корне репозитория.** Там архитектура, разбор подсистем, рецепты типовых задач и описание граблей. Второй обязательный документ — `SPRITE_COMPOSITION_RULES.md` (9 правил по графике, локализации и продакшен-безопасности).

Ниже — короткая выжимка того, что нарушать нельзя. Она не заменяет `AGENTS.md`, а страхует на случай, если ты его не открыл.

## Что за проект

Кооперативный рогалик в 2D пиксель-арте (тёмное фэнтези): Phaser 3.90 + TypeScript + Vite. Соло или онлайн-кооп до 4 игроков через Supabase Realtime. Три класса (рыцарь/следопыт/волшебник), 4 биома, боссы, стихийные комбо, предметы, мета-прогрессия. Витрина — Яндекс Игры; `degtyarikup-ui.github.io` — наш тестовый стенд.

## Правила

**1. Прогоняй `npm run check` перед коммитом.** Это линтер + тесты + сборка, и ровно это же гоняет CI перед деплоем — красный check означает, что на сайт изменения не попадут. Однажды сломанная сборка неделю не доезжала до прода, потому что её никто не заметил.

**2. Пушь каждую законченную итерацию.** Над проектом работают двое, результат смотрят на общем сайте — не копи изменения локально. Порядок: `npm run check` → если зелено, коммит с осмысленным сообщением → **`git pull --rebase`** → `git push`. Если проверка падает — чини, не коммить.

**Обязательно убедись, что пуш реально прошёл**, а не только что команда что-то напечатала: `git log -1 --format=%h origin/main` должен показать твой коммит. Второй участник пушит в ту же ветку `main`, и если он успел раньше, твой `git push` будет отклонён как non-fast-forward — это уже случалось, и выглядело как «запушил, но на сайте ничего нет». Лечится `git pull --rebase` и повторным пушем. Пушь связные работающие порции, а не каждое промежуточное сохранение. Сайт обновится сам (сразу или в течение 10 минут). Сломанная сборка сайт не уронит — деплой просто не выполнится, останется прошлая версия, — но сайт молча перестанет обновляться, так что при отсутствии изменений дольше 10–15 минут проверь вкладку Actions.

**3. Ассеты только из `public/assets/` и только через `asset()`** (`src/gfx/pack.ts`). Папка `vendor/` — это библиотека исходных арт-паков для выбора спрайтов, **в сборку она не попадает**. Загрузка по сырому пути `vendor/...` работает на `npm run dev` и даёт 404 в проде. Так уже потеряли 23 файла. Нужен спрайт из пака — скопируй его в `public/assets/`.

**4. Дебаг-меню — только через `isDebugAllowed()`** (`src/debug/access.ts`). Ни кнопок, ни обработчиков `F1`/`` ` `` в обход этой функции, и проверять надо **до** создания объектов, а не внутри `openDebugMenu()`. На Яндексе меню разработчика = отказ в публикации. Осторожно: непустой `ysdk` **не** означает «мы на Яндексе» — SDK грузится с абсолютного URL и инициализируется на любом домене.

**5. Локализация обязательна.** Новая строка интерфейса → сразу в оба словаря `RU` и `EN` в `src/i18n/index.ts`. Учти: `t()` возвращает весь словарь, пишут `t().playSolo`, а не `t('playSolo')`.

**6. Никаких юникод-эмодзи** в интерфейсе — только пиксель-арт бейджи и стилизованные теги.

**7. Две камеры.** `worldCam` (зум, мир) и `uiCam` (1:1, HUD). Мировые объекты добавляй в `worldLayer`, UI-объекты — прогоняй через `worldCam.ignore(...)`. Иначе элемент отрисуется дважды или уедет вместе с миром. `setScrollFactor(0)` от зума **не** спасает.

**8. Сетевые разовые действия — счётчиками, а не булями.** Ввод шлётся с прореживанием (~20 Гц), булев фронт потерялся бы между отправками. Смотри `attackSeq`/`interactSeq` и `consumeRemoteEdge` в `GameScene`. Хост считает всё, гость только рисует.

**9. Y-сортировка**: у мировых объектов `depth = DEPTH.YSORT_BASE + y`, обновляй при движении. Имена текстур и анимаций — константами в `src/gfx/registry.ts`, не строками по месту.

## Полезно знать

- Пуши через GitHub App (в том числе из Antigravity) **не запускают** GitHub Actions — это защита GitHub от рекурсии. В `.github/workflows/deploy.yml` стоит крон раз в 10 минут, который досылает недеплойнутые коммиты.
- **Изменения появляются на сайте не сразу: до ~20 минут.** Крон (до 10 мин) + прогон (~1 мин) + кэш `index.html` на Pages (`max-age=600`, до 10 мин). Кэш особенно обманчив: страница тянет старый хешированный бандл целиком, лечится жёсткой перезагрузкой (Ctrl/Cmd+Shift+R). **Не делай выводов и не чини пайплайн, пока не сверил штамп сборки** в правом нижнем углу меню (он же в консоли) с `git log -1 --format=%h origin/main`. Совпал — код на сайте твой. Деплоить в обход, пушем в ветку `gh-pages`, бесполезно: Pages настроен на источник GitHub Actions и эту ветку игнорирует.
- Уровни свёрстаны вручную, не процедурно: 4 функции-строителя в `src/world/level1.ts`, по одной на биом.
- Звук полностью процедурный (Web Audio), аудиофайлов в проекте нет — новый звук пишется функцией синтеза в `src/audio/SoundFX.ts`.
- Самый большой файл — `src/scenes/GameScene.ts` (~3400 строк), туда идёт почти любая правка геймплея.
- Тесты — в `tests/` (Vitest, вся пачка < 1 сек). Покрыта чистая логика: инварианты генерации уровней, правила §7/§8, боевые системы, гейт дебага. Добавляешь чистую логику — добавь тест. Всё, что требует живого Phaser или сети, проверяется только в браузере.

Если меняешь что-то из описанного здесь или в `AGENTS.md` — обнови документацию в том же коммите. Устаревшая документация хуже отсутствующей.

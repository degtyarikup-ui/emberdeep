# Emberdeep — руководство для ИИ-агентов

Прочти этот файл целиком перед первой правкой. Здесь описано, что за игра, как устроен код, куда смотреть и на какие грабли легко наступить. Проект правят разные агенты (Claude Code, Antigravity) — держи документ в актуальном состоянии, если меняешь что-то из описанного.

Второй обязательный документ — **[SPRITE_COMPOSITION_RULES.md](SPRITE_COMPOSITION_RULES.md)**: 9 жёстких правил про графику, локализацию и продакшен-безопасность. Они не рекомендации, их нарушение ломает релиз.

---

## 1. Что за игра

**Emberdeep** — кооперативный рогалик-кроулер в 2D пиксель-арте, тёмное фэнтези. Вид сверху, WASD + мышь, забег по этажам подземелья.

- **Соло или онлайн-кооп до 4 игроков** (комнаты по 5-символьному коду, транспорт — Supabase Realtime). Локальный кооп на одной клавиатуре был явно отвергнут — не предлагай его.
- **Три класса**: Рыцарь (ближний бой), Следопыт (лук), Волшебник (посох, энергошары).
- **Структура забега**: спуск по этажам (`depth` 1, 2, 3…), на каждом — зачистка, сундуки, святилища, алтарь с боссом, лестница вниз. Смерть = конец забега.
- **Прогрессия между забегами**: «угли» (embers) тратятся на постоянные апгрейды у костра.
- **Целевые платформы**: Яндекс Игры (основная витрина, есть SDK, реклама, IAP, облачные сохранения) + GitHub Pages как наш тестовый стенд.
- **Язык**: интерфейс русский и английский, RU по умолчанию. Все игровые строки обязаны быть в обоих словарях (правило §7).

## 2. Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
npm run check      # ← ОБЯЗАТЕЛЬНО перед коммитом: линтер + тесты + сборка
```

Отдельные шаги, если нужно: `npm run lint`, `npm run test` (`test:watch` для режима наблюдения), `npm run build`.

`npm run check` — единственный автоматический контроль качества и **то же самое, что гоняет CI перед деплоем**: если он красный, изменения на сайт не попадут. Уже был случай, когда сломанная сборка неделю не доезжала до прода, потому что её никто не заметил.

### Что покрыто тестами

Тесты лежат в `tests/`, гоняются на Vitest в jsdom, вся пачка отрабатывает меньше чем за секунду. Покрыта чистая логика, не рендер:

- **`level.test.ts`** — инварианты генерации уровней для всех биомов: спавн, алтарь и выход стоят на проходимой земле; ни один враг, сундук, святилище или фляга не оказался в стене или внутри твёрдого декора; ничего не наложено на одну клетку; при одной глубине уровень строится детерминированно (на это опирается кооп — синхронизируется только состояние сущностей, а геометрия должна совпасть у всех). Этот набор при первом же запуске нашёл трёх врагов, заспавненных в замёрзшем озере на 4-й глубине.
- **`rules.test.ts`** — механическая проверка правил §7 и §8: словари RU и EN содержат один и тот же набор ключей и нигде не пустые; ни в одном исходнике нет эмодзи (кроме нескольких намеренно монохромных типографских знаков вроде `✦`).
- **`systems.test.ts`** — стихийные комбо (в том числе симметричность: реакция не должна зависеть от порядка наложения), реестр предметов, экономика мета-прогрессии.
- **`debugGate.test.ts`** — `isDebugAllowed()` во всех средах. Здесь уже была регрессия, так что случаи зафиксированы явно.

Добавляешь чистую логику — добавь и тест. Всё, что требует живого Phaser, canvas или сети, тестами не покрывается: проверяй такое в браузере.

Стек: **Phaser 3.90** (WebGL, Arcade Physics, Light2D) + **TypeScript** + **Vite 6**.

## 3. Карта проекта

```
src/
  main.ts              точка входа: ждёт Yandex SDK, затем создаёт Phaser.Game
  scenes/              Boot → Menu → (Lobby) → Game
  entities/            Player, Enemy, BossEnemy, снаряды
  world/               генерация уровней и биомы
  combat/              элементальная система и комбо
  items/               артефакты, подбираемые в забеге
  meta/                прогрессия между забегами (угли, апгрейды)
  achievements/        достижения
  ui/                  HUD-компоненты (не GameObject'ы, обычные классы)
  gfx/                 текстуры, атласы, анимации, реестр ключей
  audio/               процедурный синтез звука на Web Audio
  net/                 мультиплеер поверх Supabase Realtime
  i18n/                RU/EN словари
  yandex/              обёртка над Yandex Games SDK
  debug/               гейт доступа к дебаг-меню
public/assets/         ВСЯ графика, которая грузится в рантайме
vendor/                исходные арт-паки — библиотека для выбора, В СБОРКУ НЕ ПОПАДАЕТ
```

### Поток сцен

`SCENE` — в [`src/scenes/keys.ts`](src/scenes/keys.ts): `Boot`, `Menu`, `Lobby`, `Game`.

1. **BootScene** — грузит ~70 ассетов, строит процедурные текстуры и атласы, регистрирует анимации, затем шрифты → `Menu`.
2. **MenuScene** — выбор класса, апгрейды у костра, достижения, переключение языка. Соло → сразу `Game`; кооп → `Lobby`.
3. **LobbyScene** — создание/подключение к комнате по коду, список игроков. Хост жмёт «Начать» → у всех `Game`.
4. **GameScene** — сам забег.

## 4. Ключевые подсистемы

### GameScene — сердце игры

[`src/scenes/GameScene.ts`](src/scenes/GameScene.ts), ~3400 строк. Самый большой файл; почти любая правка геймплея идёт сюда.

Отвечает за: инстанцирование уровня, спавн сущностей, симуляцию (если хост), все взаимодействия (сундуки, святилища, алтарь, лестница, фляги, монеты, разрушаемые объекты, деревья), элементальные хазарды и комбо, HUD, экраны конца, рекламу, дебаг-меню, кодирование/декодирование сетевых снапшотов.

Порядок в `update(_time, delta)`:
1. Тик хитстопа и тряски экрана
2. Тоглы Tab/I (окно статов), Esc
3. Ранний выход, если `frozen`
4. Локальный ввод → `myPlayer.update()`; счётчики `mySeq.attack/interact`
5. Мерцание факелов, свет за игроком
6. **Развилка: `updateGuestFrame(delta)` для гостя, иначе `updateHostFrame(delta)`**
7. Шкала угрозы, снаряды босса, стрелы, монеты, камера
8. Обновление HUD

Важные конструкции:
- **Две камеры.** `worldCam` (зум 1.35–2.1, следит за центром отряда) и `uiCam` (1:1, только HUD). Так сделано потому, что `setScrollFactor(0)` **не** избавляет объект от зума камеры. Мир добавляется в `worldLayer`, который `uiCam.ignore(...)`; каждый UI-объект — `worldCam.ignore(...)`. Забудешь ignore — элемент отрисуется дважды или уедет.
- **Y-сортировка**: у мировых объектов `depth = DEPTH.YSORT_BASE + y`. Обновляй при движении.
- **Шкала угрозы** — `THREAT_TIERS`, растёт от времени забега (0/90/210/360/540 сек), усиливает врагов.

### Уровни и биомы

[`src/world/level1.ts`](src/world/level1.ts) и [`src/world/biomes.ts`](src/world/biomes.ts).

**Уровни свёрстаны вручную, а не сгенерированы процедурно.** Есть пять функций-строителей, по одной на биом, с захардкоженными координатами рек, мостов, зданий, комнат, алтаря и выхода. Случайность только в разбросе мелкого декора — через детерминированный `prand(seed)` из `gfx/shapes.ts`, засеянный от `depth`.

`buildLevel1(depth)` выбирает строителя по `getBiomeForDepth(depth).id`:

| Биом | Глубина | Строитель |
|---|---|---|
| `forest` — Темный Лес | 1 | `buildDarkForestLevel` |
| `ruins` — Руины | 2 | `buildAncientRuinsLevel` |
| `catacombs` — Катакомбы | 3 | `buildPrisonCatacombsLevel` |
| `depths` — Глубины Катакомб | 4 | `buildCatacombDepthsLevel` |
| `void` — Бездна | 5+ | `buildAstralAbyssLevel` |

Сетка `COLS=60 × ROWS=38`, тайл `TILE_SIZE=32`. Строители работают на семантической сетке (`FLOOR/WALL/PATH/WATER_DEEP/BRIDGE/SNOW/ICE/RAIL/...`), затем 8-соседский автотайлинг превращает её в индексы `TILE_INDEX`. Возвращается `LevelData`: `biome, data, spawn, torches, bonfires, trees, decorations, flasks, chests, shrines, altar, exit, enemies`.

### Сущности

[`src/entities/`](src/entities/)

- **`Player.ts`** — `HeroClass = 'knight'|'ranger'|'wizard'`. Скорость/кулдаун атаки: 130/360, 145/620, 135/480. Спецатака (`trySpecial`): вихрь / веер из 5 стрел / суперновая из 8 энергошаров. Геттеры считают итоговые статы из предметов + мета-бонусов: `moveSpeed`, `attackDamage`, `critChance`, `leechChance`, `immortalCharges`.
- **`Enemy.ts`** — `EnemyKind = 'imp'|'skeleton'`. Полноценный FSM: `patrol → alert → chase → windup → lunge → recovery → backstep`, плюс расталкивание в толпе. `updateAI(...)` возвращает `true`, если враг попал по игроку. `applyElement(...)` навешивает статус и может вернуть комбо.
- **`BossEnemy.ts`** — двухфазный Архидемон. `updateBoss(...)` возвращает `BossActionOutput { landedMelee, projectiles, minionSpawns }` — вызывающая сторона обязана разложить снаряды и миньонов по сцене.
- **Снаряды** (`ArrowProjectile`, `EnergyProjectile`, `BossProjectile`) — не физические тела; двигаются вручную в `update(delta)`, возвращают `false`, когда пора уничтожать. `hitEntityIds: Set<number>` не даёт одному снаряду попасть дважды при пробитии.

### Боевые системы

- **[`combat/ElementalSystem.ts`](src/combat/ElementalSystem.ts)** — чистые данные + функции, без классов. `ElementType = 'fire'|'frost'|'lightning'|'poison'`. Стихии вешаются на 4 слота действий: `attack`, `skill`, `dash`, `onKill`. `checkElementalCombo(incoming, status)` даёт 4 реакции: огонь+яд → `toxic_burst`, лёд+молния → `shatter`, огонь+лёд → `thermal_shock`, молния+яд → `static_plague`.
- **[`items/registry.ts`](src/items/registry.ts)** — 13 артефактов трёх редкостей. `getRandomItem()` **не принимает аргументов** (60% common / 32% uncommon / 8% legendary). Часть предметов задаёт `element` + `elementSlot` — так игрок и получает стихии.
- **[`meta/MetaManager.ts`](src/meta/MetaManager.ts)** — синглтон `MetaManager.get()`. Угли и 5 апгрейдов (`vitality, might, agility, fortune, bounty`). `getBonuses()` отдаёт `{extraHp, damageMultiplier, speedMultiplier, extraCrit, startGold}` — читается в конструкторе `Player`. Хранится в `localStorage['emberdeep_meta']` и дублируется в облако Яндекса.
- **[`achievements/`](src/achievements/)** — 7 достижений, `AchievementManager.get()`, тосты и `localStorage`.

### Графика

[`src/gfx/`](src/gfx/) — читай в таком порядке:

- **`registry.ts`** — единственный источник имён. `TEXTURE` (~70 ключей вида `'tex-...'`), `ANIM`, `FONT`, `DEPTH`, `PLAYER_TINTS`. Никогда не пиши строковый ключ текстуры руками — добавь константу сюда.
- **`pack.ts`** — `asset('name.png')` возвращает `${import.meta.env.BASE_URL}assets/name.png`. **Все пути к ассетам обязаны идти через него** (см. §6). Плюс `buildAtlasFromPack(...)` — вырезает набор прямоугольников из исходных листов в один атлас.
- **`actors.ts`** — `ACTORS = { HERO, ORC, SKELETON }`, у каждого `idle/run/death` отдельным файлом со своим размером кадра. `preloadActor` / `createActorAnims`.
- **`PixelUI.ts`** — современный набор UI-текстур (панели, слоты, полосы), рисуется процедурно в canvas на старте. `UIAtlas.ts` — портреты, иконки предметов (`ITEM_SPRITE_MAP`).
- **`AnimationManager.ts`** — `EntityAnimController`: FSM анимаций с приоритетами и прерываемостью (смерть не перебьётся бегом).
- **`tiles.ts`** — `TILE_INDEX`, сборка тайлсета с экструзией 1px (`TILE_MARGIN=1`, `TILE_SPACING=2`) против швов в WebGL.

### UI

[`src/ui/`](src/ui/) — обычные классы, не Phaser-объекты. Каждый держит свой `Container` на `DEPTH.UI`, со `setScrollFactor(0)` и `cameras.main.ignore(...)`.

`HeroFrame` (портрет, HP, золото, угли) · `ActionBar` (4 слота, радиальный кулдаун) · `InventoryTray` (иконки предметов) · `BossBar` · `PartyFrames` (союзники в коопе) · `StatsModal` (лист персонажа, Tab/I) · `Tooltip` (общий синглтон).

Создаются в `GameScene.create()`, обновляются в хвосте `update()`. Обрати внимание на API: у `InventoryTray` метод **`updateItems(itemsMap)`**, принимает словарь, а не игрока.

### Сеть

[`src/net/`](src/net/) — Supabase Realtime broadcast.

**Модель авторитета: хост считает всё, гости только рисуют.**

- Хост — слот 0, единственный, кто считает ИИ, урон, лут и рассылает снапшоты (~15 Гц).
- Гость шлёт `InputPayload` (~20 Гц) и интерполирует чужие позиции из снапшотов. Своя позиция предсказывается локально и **не** перезаписывается снапшотом (нет резинки), а вот HP/золото/предметы приходят от хоста.
- **Атака и взаимодействие передаются счётчиками `attackSeq` / `interactSeq`, а не булями.** Ввод шлётся с прореживанием, и булев фронт мог бы потеряться между отправками. Хост ловит новое нажатие через `consumeRemoteEdge` (диффом счётчика). Добавляешь новое разовое действие — делай так же.
- События: `roster`, `input`, `snapshot`, `start`, `transition` + presence-синхронизация.
- Код комнаты — 5 символов из алфавита без `0/O/1/I`.

### Звук

[`src/audio/SoundFX.ts`](src/audio/SoundFX.ts) — **полностью процедурный синтез на Web Audio, ни одного аудиофайла**. Всё собирается из осцилляторов, шума и фильтров. Синглтон `SoundFX` (экспортируется инстанс, не класс). Есть 2D-пространственный звук: `registerSpatialEmitter(...)` + `updateSpatial(listenerX, listenerY, delta)` каждый кадр.

Новый звук = новая функция синтеза, а не новый ассет.

### Локализация

[`src/i18n/index.ts`](src/i18n/index.ts). `t()` возвращает **весь словарь**, поэтому пишут `t().playSolo`, а не `t('playSolo')`. Порядок определения языка: `localStorage` → `navigator.language` → `ru`. Внутри Яндекса язык навязывается из SDK.

### Яндекс

[`src/yandex/yandexSdk.ts`](src/yandex/yandexSdk.ts) — синглтон `YandexSDK.get()`. Инициализация **ждётся до создания `Phaser.Game`** (требование платформы). Реклама с кулдауном 90 сек, rewarded-видео (воскрешение), IAP, облачные сохранения, пауза/резюм.

Вне Яндекса SDK не находится за 2.5 сек, `ysdk` остаётся `null`, и все методы тихо деградируют (реклама — no-op, rewarded сразу выдаёт награду для удобства разработки). Один и тот же билд работает и там, и на GitHub Pages — за это отвечает `base: './'` в `vite.config.ts`.

## 5. Как сделать типовые вещи

### Добавить спрайт

1. Положи PNG в **`public/assets/`**. Если берёшь из пака в `vendor/` — **скопируй файл**, не ссылайся на `vendor/` (см. §6).
2. Добавь ключ в `TEXTURE` (и `ANIM`, если анимирован) в `src/gfx/registry.ts`.
3. Загрузи в `BootScene.preload()` через `asset('file.png')`.
4. Если анимация — зарегистрируй в `BootScene.create()`.
5. Чтобы появился на уровне — добавь запись в массив `decorations` нужного строителя в `world/level1.ts`.

### Добавить врага

`STATS` в `entities/Enemy.ts` (нужен `ActorClips` в `gfx/actors.ts`), расширь `EnemyKind`, добавь в массив `enemies` строителя уровня. Проверь, что новый `kind` корректно ездит в снапшоте (`EnemySnapshot.kind` — строка).

### Добавить предмет

`ITEMS` в `items/registry.ts` + иконка в `ITEM_SPRITE_MAP` (`gfx/UIAtlas.ts`). Если предмет влияет на статы — правь соответствующий геттер в `Player.ts`.

### Добавить чит в дебаг-меню

Массивы `cheats` в `GameScene.openDebugMenu()` и `MenuScene.openDebugMenu()`. Каждый пункт — `{ id, label, active, onClick }`. **Не создавай ничего в обход `isDebugAllowed()`.**

## 6. Грабли (тут уже ломали)

### Ассеты только из `public/assets/`, только через `asset()`

`vendor/*/source/` содержит полные распакованные арт-паки — это **библиотека для выбора**, чтобы агент мог найти подходящий спрайт. **Vite копирует в сборку только `public/`.** Загрузка по сырому пути `vendor/...` работает на `npm run dev` (dev-сервер отдаёт корень репозитория) и даёт 404 в проде. Так уже потеряли 23 файла — волшебник, шипы, фонтаны и посох просто не грузились на сайте.

Сырые пути ещё и мимо `import.meta.env.BASE_URL`, что ломает не-корневой base.

**Правило: всё, что грузится в рантайме, лежит в `public/assets/` и запрашивается через `asset()`.**

### Пуши агентов не запускают CI

GitHub намеренно не порождает событие `push` для пушей, сделанных токеном GitHub App — а именно так пушит Antigravity. Коммиты появляются в ветке, workflow не стартует, прод молча отстаёт. Так уже пропустили сломанную сборку.

Обходной путь уже настроен: в `.github/workflows/deploy.yml` есть расписание `*/10 * * * *`, которое сравнивает HEAD `main` с SHA последнего деплоя и собирает, если они разошлись. **Значит, твой пуш доедет до прода максимум за 10 минут** — но проверить `npm run build` локально всё равно обязан ты.

### Дебаг-меню и продакшен (правило §9)

Единственная проверка — `isDebugAllowed()` из [`src/debug/access.ts`](src/debug/access.ts):

```
DEV-режим  ИЛИ  ?debug=1  ИЛИ  хост из INTERNAL_TEST_HOSTS
```
и **жёсткое вето**: если Yandex SDK реально поднялся (`YandexSDK.get().ysdk`), дебаг выключен всегда.

`degtyarikup-ui.github.io` — наш с напарником стенд, туда игроки не заходят, поэтому там дебаг включён намеренно. На Яндексе его быть не должно ни при каких условиях: модератор, случайно вызвавший меню разработчика, — это отказ в публикации.

Проверять надо **до создания объектов**: `buildDebugUI()` выходит раньше, чем появится хоть один элемент, а обработчики `F1` / `` ` `` вообще не регистрируются. Проверки внутри `openDebugMenu()` недостаточно.

**Важно: `ysdk` непустой ≠ «мы на Яндексе».** `index.html` грузит SDK с абсолютного `https://yandex.ru/games/sdk/v2`, поэтому `YaGames.init()` успешно проходит на любом домене — на нашем стенде `ysdk` есть, но `environment.app.id` пустой. Проверка «если есть `ysdk`, значит витрина» однажды уже вырубила дебаг там, где он был нужен. Настоящая витринная сессия определяется в `debug/access.ts` так: страница внутри iframe (`window.self !== window.top`, либо доступ к `top` кидает исключение из-за cross-origin) **или** непустой `environment.app.id`.

### Обе камеры

Забыл `worldCam.ignore(uiElement)` — элемент отрисуется в мире. Забыл добавить мировой объект в `worldLayer` — он попадёт на UI-камеру.

### Никаких юникод-эмодзи (правило §8)

В интерфейсе только пиксель-арт бейджи и стилизованные теги. Эмодзи ломают пиксельную стилистику и рендерятся по-разному в браузерах.

### Локализация обязательна (правило §7)

Новая строка в UI → сразу в оба словаря `RU` и `EN` в `i18n/index.ts`.

## 7. Сборка и деплой

| Куда | Как |
|---|---|
| **GitHub Pages** (тестовый стенд) | Автоматически из `main` через `.github/workflows/deploy.yml`: на `push` и по крону раз в 10 минут. → https://degtyarikup-ui.github.io/emberdeep/ |
| **Яндекс Игры** | `npm run build` → ZIP из `dist/`. Работает благодаря `base: './'`. |

Ключи Supabase (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) лежат в `.env.local` локально и прописаны в `env:` workflow. Это публикуемые anon-ключи, они по замыслу видны в клиентском бандле — не секрет, прятать не надо.

### Пушить после каждой законченной итерации

Проект правят двое, каждый со своим агентом, и обе стороны смотрят результат на общем сайте. Поэтому **законченную порцию работы надо доводить до `main`, а не копить локально.** Порядок:

1. `npm run check` — если падает, **чинишь и не коммитишь**.
2. Коммит с осмысленным сообщением (что и зачем, а не «фиксы»).
3. `git pull --rebase` — второй мог запушить, пока ты работал.
4. `git push`.
5. **Проверь, что пуш дошёл:** `git log -1 --format=%h origin/main` должен показать твой коммит.

Пятый шаг не формальность. В `main` пушат двое, и если второй успел раньше, твой `git push` отклоняется как non-fast-forward. Агент при этом легко рапортует об успехе, не посмотрев код возврата, — и получается ровно то, что уже было: «я запушил, а на сайте ничего нет», хотя коммита нет и в репозитории. Лечится `git pull --rebase` и повторным пушем.

«Законченная итерация» — это связная работающая порция, а не каждое промежуточное сохранение: история должна читаться, а не состоять из шума.

**Сломанная сборка не уронит сайт.** В workflow `deploy` зависит от `build`: если проверки падают, деплой просто не выполняется и на сайте остаётся прошлая рабочая версия. Опасность другая — сайт **молча перестаёт обновляться**, и это легко не заметить.

### Сколько ждать изменений на сайте

Складывается из трёх задержек, и в сумме это **до ~20 минут при полностью исправном пайплайне**:

| Этап | Задержка |
|---|---|
| Пуш из Antigravity не порождает событие `push`, ждём крон | до 10 мин |
| Сам прогон (линтер + тесты + сборка + деплой) | ~1 мин |
| GitHub Pages отдаёт `index.html` с `cache-control: max-age=600` | до 10 мин |

Третий пункт коварнее всего: в `index.html` прописано имя хешированного бандла, поэтому закэшированная страница тянет **старый бандл целиком**. Жёсткая перезагрузка (Ctrl/Cmd+Shift+R) или приватное окно снимают это сразу.

**Как проверить, а не гадать.** В правом нижнем углу меню стоит штамп сборки — короткий хеш коммита и время. Он же печатается в консоль при старте (`[Emberdeep] build ...`). Сверь его с последним коммитом в `main`:

```bash
git log -1 --format=%h origin/main
```

Совпало — на сайте твой код, ищи проблему в самой правке. Не совпало — либо ещё не прошли задержки выше, либо смотри вкладку Actions: там красный прогон.

Полезно: `gh run list --repo degtyarikup-ui/emberdeep --limit 5` показывает последние прогоны, а сравнение задеплоенного SHA с HEAD делается так:

```bash
gh api "repos/degtyarikup-ui/emberdeep/deployments?environment=github-pages&per_page=1" --jq '.[0].sha'
```

**Не пытайся деплоить в обход** — например, пушем собранных файлов в ветку `gh-pages`. Pages настроен на источник «GitHub Actions» (`build_type: workflow`), такая ветка просто игнорируется, а время потрачено.

- Состав комнаты фиксируется на старте, подключиться в середине забега нельзя.
- Бандл ~1.9 МБ одним чанком, код-сплиттинга нет.
- Тестов нет вообще.
